Cheatsheet + Settings — 5 Variants

Variant 4 (cheatsheet) extended to handle configurable settings — format, quality, save folder — without losing the dense, glanceable reference feel.

Recording section is the test case because it carries the most settings. Every variant must still feel like a cheatsheet first, a settings panel second.

A tiny gear lives next to each section title. Click it and a settings strip slides in above that section's rows. The cheatsheet stays primary; settings are revealed on demand and collapse when done.

Tradeoffs

  • Inline Disclosure — most familiar (HN-style "click ⚙️ to expand"). Hides clutter by default. Best if some sections have no settings at all. Build cost: low.
  • Sticky Inspector — widest popover but every setting is one focus away. Feels like a real app. Best if most sections will eventually grow settings. Build cost: medium (focus state + width).
  • Inline Chips — zero modes, zero clicks to see current state. Cluttered if any section has >3 settings. Best for "advanced status at a glance." Build cost: low.
  • Bottom Drawer — preserves the cheatsheet completely. Single, predictable place for "all configuration." Worst at letting the user see settings while scanning the sheet (one or the other). Build cost: low–medium.
  • :set Mode — most opinionated, most Macaveli-character. Setting keys (record.format) double as identifiers we can document. Feels right for a hotkey app. Build cost: medium (two view states, same widget).

Recommendation: if you want consistency, :set Mode — it reuses the cheatsheet grid for both states, so there's only one renderer. If you want the simplest path, Inline Disclosure.
